# 맘마중(Mom's Journey) — 연구 방향 및 진행 계획

> 최종 수정일: 2026-04-26

---

## 1. 프로젝트 방향 전환 배경

### 기존 방향
모성보호 HR 사각지대 분석을 위한 챗봇 서비스 개발.
법제처 API 기반 RAG 챗봇, LDA 토픽 모델링, 감성분석 기반 제품 추천,
이동 경로 스트레스 지수 산출 등 다양한 기능을 구현하였다.

### 전환 이유
단순히 "동작하는 서비스"를 만드는 것은 캡스톤 수준을 넘는 연구 기여점으로 보기 어렵다.
논문 수준의 기여가 되려면 **어떻게 만들었는가에 독자적인 방법론**이 있어야 한다.

### 새로운 방향
기존 구현 시스템은 데모 및 연구 기반으로 유지하되,
아래 두 가지를 핵심 연구 문제로 설정한다.

---

## 2. 핵심 연구 문제 (Research Questions)

### RQ1. LLM 기반 합성 데이터 생성
> "모성보호 HR 위반 사례처럼 희소하고 민감한 도메인에서,
> LLM을 활용한 합성 데이터 생성 시 어떤 전략이
> 데이터의 다양성·현실성·레이블 정확도를 높이는가?"

- 실제 커뮤니티 게시글 수집이 어려운 상황에서 LLM이 대안이 될 수 있는가
- Prompt-based / RAG-augmented / Self-Refinement 전략 간 품질 차이는 어느 정도인가
- 생성된 데이터의 품질을 어떤 지표로 측정할 것인가

### RQ2. LLM-as-a-Judge 평가 프레임워크
> "RAG 챗봇이 생성한 모성보호 법령 답변을 LLM이 자동 채점할 때,
> Judge LLM의 환각과 편향을 어떻게 완화하면 신뢰할 수 있는 평가가 가능한가?"

- 모성보호 법령 도메인에 특화된 평가 기준(rubric)은 어떻게 설계해야 하는가
- Judge LLM의 편향(Position bias, Verbosity bias 등)이 평가에 미치는 영향은 어느 정도인가
- 편향 완화 방법(Panel of Judges, Calibration) 적용 전후 신뢰도는 어떻게 달라지는가
- Human annotation과의 일치율(Cohen's Kappa)은 어느 수준인가

## 3. 전체 연구 흐름

```
[Phase 1] 평가 기준 설계
    법령 답변 평가 rubric 정의
    (법령 정확성 / 근거 명시 / 완전성 / 할루시네이션)
            ↓
[Phase 2] 합성 데이터 생성 파이프라인 구축
    질문-정답 쌍 생성 전략 설계 및 비교 실험
    (Prompt-based / RAG-augmented / Self-Refinement)
            ↓
[Phase 3] RAG 챗봇 답변 생성
    기존 법령 RAG 챗봇으로 합성 질문에 대한 답변 생성
            ↓
[Phase 4] LLM-as-a-Judge 평가 시스템 구축
    Judge LLM이 rubric 기준으로 챗봇 답변 자동 채점
            ↓
[Phase 5] Judge 신뢰도 분석 및 개선
    편향 측정 → 완화 방법 적용 → Human annotation 비교
            ↓
[Phase 6] 결과 분석 및 정리
    데이터 생성 전략별 품질 비교
    Judge 신뢰도 향상 전후 비교
    한계점 및 향후 연구 방향 도출
```

## 4. 단계별 세부 계획

### Phase 1. 평가 기준(Rubric) 설계
**목표:** Judge LLM이 사용할 채점 기준표 완성

| 평가 항목 | 설명 | 배점 |
|-----------|------|------|
| 법령 정확성 | 언급한 조문 번호와 내용이 실제 법령과 일치하는가 | 0~3점 |
| 근거 명시 | 조문명(예: 근로기준법 제74조)을 구체적으로 인용했는가 | 0~2점 |
| 완전성 | 질문에 필요한 핵심 내용이 빠짐없이 포함되었는가 | 0~3점 |
| 할루시네이션 | 존재하지 않는 법령이나 내용을 만들어냈는가 | 0~2점 |

- 각 항목별 채점 기준 상세 서술 필요 (예: 3점 = 완전 정확, 2점 = 부분 정확, ...)
- 팀 전체 논의를 통해 확정
- 법령 전문가 검토 여부 고려

**산출물:** `rubric_v1.md`

---

### Phase 2. 합성 데이터 생성 파이프라인 구축
**목표:** 모성보호 법령 Q&A 테스트셋 생성 (질문-정답 쌍 100~200개)

#### 2-1. 질문 유형 정의
기존 LDA 토픽 모델링 결과를 활용해 질문 유형을 분류한다.

| 유형 | 예시 질문 |
|------|-----------|
| 복직 관련 | "육아휴직 후 복직 시 동일 직무를 보장받을 수 있나요?" |
| 단축근무 관련 | "임신 중 근로시간 단축을 신청하면 회사가 거절할 수 있나요?" |
| 임신 보호 관련 | "임신 사실을 이유로 해고하는 것이 불법인가요?" |
| 급여 관련 | "출산전후휴가 기간 중 급여는 어떻게 지급되나요?" |
| 소규모 사업장 관련 | "5인 미만 사업장에도 육아휴직이 적용되나요?" |

#### 2-2. 생성 전략 3가지 비교 실험

**전략 A. Prompt-based Generation**
- 법령 조문 없이 LLM에게 직접 질문-정답 쌍 생성 요청
- 가장 단순하지만 할루시네이션 위험이 높음
- 베이스라인으로 활용

**전략 B. RAG-augmented Generation**
- 법제처 법령 조문을 컨텍스트로 제공하고 생성
- 실제 법령에 근거한 정답 생성 가능
- 현재 구축된 ChromaDB 벡터스토어 활용

**전략 C. Self-Refinement Generation**
- 전략 B로 초안 생성 → LLM이 스스로 검토 및 수정 반복
- 품질이 가장 높을 것으로 예상되나 비용 증가

#### 2-3. 생성 데이터 품질 평가 지표
- **다양성(Diversity):** 질문 유형 분포의 균일성
- **현실성(Realism):** 실제 커뮤니티 게시글과의 유사도
- **레이블 정확도(Label Accuracy):** 생성된 정답이 실제 법령과 일치하는 비율

**산출물:** `data/synthetic_qa_dataset.json` (전략별 각 100개)

---

### Phase 3. RAG 챗봇 답변 생성
**목표:** Phase 2에서 생성한 질문을 기존 RAG 챗봇에 입력하여 답변 수집

- 기존 `chatbot/api.py` 활용
- 질문당 챗봇 답변 1개 생성
- 답변과 함께 검색된 법령 조문(출처) 함께 저장
- 입력 질문 / 정답(gold answer) / 챗봇 답변 3가지를 쌍으로 구성

**산출물:** `data/chatbot_responses.json`

---

### Phase 4. LLM-as-a-Judge 평가 시스템 구축
**목표:** Phase 1 rubric 기준으로 챗봇 답변을 자동 채점하는 시스템 구현

#### 4-1. Judge 프롬프트 설계
```
[역할]
당신은 모성보호 법령 전문 평가자입니다.

[평가 대상]
질문: {question}
정답(참조): {gold_answer}
챗봇 답변: {chatbot_answer}

[평가 기준]
1. 법령 정확성 (0~3점): ...
2. 근거 명시 (0~2점): ...
3. 완전성 (0~3점): ...
4. 할루시네이션 (0~2점): ...

[출력 형식]
각 항목 점수와 이유를 JSON으로 출력하시오.
```

#### 4-2. Judge 모델 선정
- 기본: GPT-4o
- 비교 실험: Claude 3.5 Sonnet, GPT-4o-mini
- 모델 간 일치율 비교 → Panel of Judges 적용 기반

**산출물:** `evaluation/judge_results.json`

---

### Phase 5. Judge 신뢰도 분석 및 편향 완화
**목표:** Judge LLM의 한계를 정량화하고 완화 방법 적용 전후 비교

#### 5-1. 편향 측정
- **Position bias:** 질문-정답 순서를 바꿨을 때 점수가 달라지는가
- **Verbosity bias:** 답변 길이와 점수의 상관관계
- **Self-enhancement bias:** Judge와 동일 회사 모델 답변에 높은 점수를 주는가

#### 5-2. 완화 방법 적용
- **Panel of Judges:** GPT-4o + Claude + GPT-4o-mini 합의 점수 사용
- **Calibration:** 답변 길이 등 불필요한 요소 점수 차감
- 적용 전후 점수 분포 비교

#### 5-3. Human Annotation 비교
- 팀원 2인이 동일 답변 30~50개를 직접 채점
- Judge 점수와의 일치율 측정 (Cohen's Kappa)
- Kappa > 0.6 이면 신뢰할 만한 수준으로 판단

**산출물:** `evaluation/bias_analysis.ipynb`, `evaluation/human_annotation.csv`

---

### Phase 6. 결과 분석 및 정리
**목표:** 실험 결과 정리 및 연구 기여점 도출

- 합성 데이터 3가지 전략(A/B/C)의 품질 비교 결과 정리
- Judge 신뢰도 향상 전후 비교 (Cohen's Kappa, 편향 측정값)
- 한국어·모성보호 도메인 특수성이 평가에 미친 영향 분석
- 한계점 및 향후 연구 방향 서술

## 7. 예상 연구 기여점

1. **모성보호 법령 특화 평가 rubric 설계**
   기존 일반 법령 벤치마크(CALRK-Bench, KCL)에 없는
   모성보호 HR 도메인 특화 평가 기준을 제안한다.

2. **희소 도메인 합성 데이터 생성 전략 비교**
   실제 데이터 수집이 어려운 민감한 HR 도메인에서
   LLM 합성 데이터 생성 전략 3가지의 품질을 실증적으로 비교한다.

3. **한국어 법령 도메인에서의 Judge 신뢰도 분석**
   다국어 환경에서 Judge 신뢰도가 낮다는 선행 연구를 한국어 법령 도메인으로 확장하고,
   편향 완화 방법의 실효성을 검증한다.
